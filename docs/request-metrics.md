# Actual DNS request metrics

Set `DIVERSION_METRICS_FILE=/var/run/diversion-dns-c/metrics.json` in the service environment and create its parent directory with private ownership. The default is off. No domain names, addresses or payloads are recorded. An owner-only atomic JSON snapshot replaces the previous one every five seconds and once on orderly shutdown; keep the destination on tmpfs. Non-regular destinations are refused and exporter errors do not stop DNS.

`version=1` identifies the schema. `pid`, `started_unix`, `uptime_ms`, `sequence` and `updated_unix_ms` identify a process and snapshot. Readers must invalidate on restart, counter decreases, stale snapshots or boot changes. `final=true` is a stopped process, not a live health signal.

`totals.requests` counts complete, valid client queries accepted by the UDP/TCP server; `completed` counts each terminal response or delivery failure once, including coalesced followers, fast cache replies, overload rejection and aborted accepted queries. Malformed packets, TCP handshakes/incomplete frames, and traffic dropped before userspace are outside the denominator. Background refresh and warm-up are excluded from client requests.

`success` means a NOERROR or NXDOMAIN response handed successfully to the local socket. NXDOMAIN is a valid negative answer, not proof an application works. SERVFAIL, REFUSED, other rcodes, no response and socket write failures count as `failed`. A successful local send cannot prove client receipt. Upstream timeout commonly becomes SERVFAIL; this snapshot does not invent a separate client-timeout counter.

Recent success rate is delta(success) / delta(completed). Recent latency is measured from acceptance of a complete valid query to terminal socket submission/failure and includes queue and TCP write waiting. It does not include client network transit. Both successful and failed completions enter latency_count/sum_us and mutually exclusive histogram buckets, whose matching upper bounds are microseconds; the last null bound is infinity. Percentiles inferred from buckets are upper-bound estimates, not exact per-query percentiles. Latest latency and completion wall time describe one actual completion. A zero denominator means no samples, not 0% or 100%.

`cache.cn` and `cache.foreign` expose existing native cache counters. Hits = fresh + stale; counted lookups = fresh + stale + cold + evicted + expired + bypass. Keep fresh and stale distinct; bypass belongs in this denominator. These are cache lookup counts, not all server requests: coalesced followers and rejected requests can differ. The two snapshots (request counters and cache) are read independently under their own synchronization, so do not assert equality between their denominators. Recent ratios use deltas from the same process. Refresh/warm counters are separate.

Run `c/tests/request_metrics_test.py --application <verified binary> --output <new directory>` without compiling. It is also selected by `scripts/validate.py` in all CI profiles. The fixture covers real loopback UDP/TCP, cache fast paths, shared requests, negative answers, SERVFAIL, restart, privacy and destination safety.
